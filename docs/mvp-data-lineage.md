# 稳研工作台数据关系与回退路径

## 来源到采用值

历史上传保存原件、SHA256、上传上下文及只读来源坐标。候选与工作副本记录解释和审核决定。只有工作表预检通过并正式提交后才产生结果版本。已提交的事实通过新版本更正或追加复测。当前采用关系单独保存，因此一次复测可以存在而仍保留原采用值。

研究表按计划行与时间点关联已有结果位置。历史建表注册这些位置，并为研究绑定样品。当前页、趋势和新交付读取采用状态。原件未给出的材料阶段及有争议的检项解释需要显式补齐。用于验证流程的模拟决定必须标明用途。

## 样品、标准与 0M

样品在项目内按批号、类别、阶段、规格、包装和用途区分。标准归档保留原件及原文条款。项目当前标准按材料范围存储显式选择，既有计划的标准引用保留文档和条款位置。历史记录自身的标准原文为来源证据，可独立出现在研究表与导出中。

放行数据按样品与标准保存版本。复制到 0M 时，新建正式稳定性结果，来源中保存所选 COA 版本、条款和样品。之后更新 COA 不会重写这个复制结果。旧研究的动态放行引用保留其原语义，研究员可显式转成快照。

## 当前展示与历史交付

清空已有采用值时记录作废事件并撤销当前采用。删除行、研究表或样品使用影响清单和指纹校验关联范围，保留旧计划、版本及原件。归档研究表的原身份和结果位置存入审计事件，释放活动位置供重新建表。

导出的研究表填写模板内带有隐藏的研究和版本元数据。回传时校验数据库、目标身份、模板结构、预览指纹和版本差异。允许选定提交子集。生成后的交付文件与其冻结快照和哈希一起保存，旧交付在后续更正或作废后仍可读。常熟受控汇总使用独立交付版式。

## 迁移与隔离

v19 添加研究表和样品归档字段以及项目用途，并初始化 TEST 沙盒。v20 添加当前标准选择关系。已有 v18 库的验收从隔离副本开始，生产切换前应通过现有备份工具保存并核对数据库以及原件。迁移事务失败会回滚，需恢复时应选取校验通过的完整备份作为新的启动目录。

日常启动使用 `start.cmd`。真实文件测试使用不同的 `--home` 与独立端口。隔离输出中的原件副本、SQLite、下载产物和逐格证据均不进入 Git。
