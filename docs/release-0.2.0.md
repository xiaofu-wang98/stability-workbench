# 0.2.0 发布说明

日期：2026-11-06。开发分支：`codex/0.2.0`。基线：`a105c2a`（0.1.5）。保留V3布局、原件、正式版本及既有核对/采用流程；不引入AI。

## 本轮范围

落实审核方案第一批：已复现的准确性修复、必要索引和事务内查询复用、普通改单值交互。可选业务注释查询、调查管理、日期筛选和平行样模型仍按实际需求后续实现。

### 准确性

- 明确方案字段中的单一编号不再要求STB(...)前缀。同方案再次上传补充/改值，沿用同一结果身份参与历史比较；从混合标题抽取编号仍保留谨慎规则。
- “原结果不汇报，现报告为98.5”等历史/否定/当前混合语句提出汇报解释问题，不能静默作为不汇报正式值；人工明确本次结果后仍保留完整原文。
- 新的共享business_notes模块用于表后说明范围与重要备注发现，支持中文月份/序数月份、英文月份、天数、明确集合和有限区间，以及当前表真实检项/方法和既有通用检项词汇。
- 识别桥接、英文复测/更正/替代等说明，仅关联和提示，不自动改变采用值或认定可比。未知检项、批次限定和未定的后续范围保留待定位状态；单独AR编号仍可只作表级提醒。
- 身份解释和汇报解释分别标记新版本。旧草稿沿用冻结解释，显式规则重解释预览可显示语义差异；正式版本、raw_json和原件不改写。旧解释的行为仍有回归覆盖。

### 性能

- schema 9新增候选upload索引、事件subject/action/sequence及project/action/sequence索引。旧迁移不改写，升级自动备份，失败回滚。
- 撤销集合按项目和当前连接的事务写入状态复用，包含当前项目的继承决定；避免每个候选扫描所有项目的撤销事件。
- 保存点回滚和事务回滚会使该集合失效，防止sqlite total_changes在回滚后保持不变造成错误复用。既有权限分区、revision与正式提交核验继续生效。
- 未重写完整结果查询、增加复杂后台缓存或更换数据库；未变化刷新沿用既有快速路径。

### 交互

- 普通“修改”首屏为结果、单位和说明。检项、时间点、方法、研究身份及标准等按需展开。
- 候选接口新增可选inherited_fields，说明本文件公共信息的继承值；原有applied_defaults含义保持不变。保存只发送实际变化，不把继承字段重复写成手工更正。
- 保留专业字段编辑、原表核对、工作副本和整表提交入口。app.html由frontend/v3源码构建。
