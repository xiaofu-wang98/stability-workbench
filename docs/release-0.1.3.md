# 0.1.3：恢复既有结果展示交互（2026-11-04）

## 恢复内容

- 批次恢复为直接点击的按钮，按当前项目真实批次生成；标签只使用已有材料类别和规格，不复制IP166E的PPQ/6000L等样例属性。
- 考察条件恢复为长期、加速、影响因素/应力、放行按钮，标签带真实条件及已收到时间范围。点击批次后只显示该批次实际条件，筛选及刷新记忆按项目隔离。
- 完整结果表默认展开，恢复检项/子结果、方法、质量标准原文、全部时间点及结论列。可主动切换紧凑滚动，不再默认截成内部长表窗口；放行保留两种方向。
- 标准列展示已保存的原文记录并提示适用性未确认；结论为“未评价”。不因恢复外观而制造标准关联、限度线或合格判断。
- 趋势恢复为多检项卡片网格：宽屏四列，中等屏幕三/两列，手机一列。可绘制精确数值的检项优先；纯定性、限值及其他结果留在完整表格和折叠区，不生成假数值。
- 每张卡片独立拥有曲线、兼容批次叠加、图点来源、重读与同范围Excel/PNG导出。图表按可见区域读取，单页队列最多3个并发；错误只影响对应卡片，可独立重试。
- 保留0.1.2的正式采用值曲线和双状态表格。切换条件/项目后丢弃旧图表响应，导出仍检查项目修订及确切结果范围。
- 进入检测台账默认看已入库结果。来源核对折叠为次级入口，进入核对后有“返回已入库结果”。同一来源清单不重复重绘，异步刷新保留已展开状态，避免用户操作被打断。

## 实现范围

主要修改 `frontend/v3/result-display.js`、`v4-ledger-review.js`、`v5.css` 及生成的 `app.html`。后端只为只读分组元数据增加 `exact_numeric_count`，用于区分真正可绘制的精确采用值与限值；不改变版本、结果、权限、身份、采用决定或排序逻辑。

没有数据库迁移。继续复用既有只读展示接口、趋势规则、来源抽屉和导出核验，不重新解析原件，也不要求重新入库。

## 使用与故障定位

沿用 `start.cmd` 和原data目录。启动0.1.3后直接打开 `/?project=项目号&view=ledger`，不带upload参数即为结果展示；带upload/sheet仍定位来源核对。

若按钮或卡片仍是旧样式，先确认 `/health` 的版本并刷新页面。若单图失败，卡片保留具体错误及重读按钮；核查 `result-display.js` 的队列/选中身份和只读趋势响应，不能靠改库或模糊身份匹配绕过。标准未关联、定性或限值不画普通数值图属于既定规则。
