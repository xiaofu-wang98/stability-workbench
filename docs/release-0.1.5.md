# 0.1.5 快速批次对比

本版按用户确认的方案，将可比性页改为趋势优先，检测台账继续保持完整表格在前。用户不必先填写研究名称、逐项分组和保存配置，选中批次、条件及检项后即可只读查看曲线。

## 解决的问题

0.1.4 的“预览分组”只给出人数摘要，保存按钮在未预览或再次修改后禁用；图表须保存研究后才会读取，并位于完整表格之后。用户截图对应的 IP275 当时没有已保存研究，导致用户完成大量选择后仍看不到产出。本版将看图与保存研究拆成可独立完成的操作，并为读取、空结果、无数值、错误及单侧分组给出明确反馈。

## 使用方式

1. 进入任意真实项目的可比研究页，点击一个或多个批次按钮。批次可搜索、清空；同批的多个独立来源收在“来源／规格”内，可进一步细选，不以批号代替正式身份。
2. 点击实际收到的长期、加速、应力或放行条件，选择检项。默认选择有精确正式采用值的可用检项，也可选“全部检项”。系统自动读取首图，不要求先创建研究。
3. 身份兼容的结果同图显示；有规格／原研究编号差异时，先分别出图并提示。点击“查看差异并确认对齐”，明确勾选字段、核对当前批次／条件／检项并填写依据后，才在本次选择内叠加。方法、版本、单位、材料、用途、条件、时间单位及报告体系不能通过此操作混合。
4. 需要时展开“批量分组”，勾选多个批次后设为按批次对比、变更前或变更后。不强制分组；只有变更前或只有变更后时仍显示曲线，并提示尚不能进行前后比较。不按名称、日期或产能猜测角色。
5. 点击“完整结果”才读取和渲染当前范围表格，保留展示值、正式采用值、标准原文、未评价状态及来源入口。返回趋势页不要求再次生成同一张图。
6. 可直接导出当前范围或单组报告，不必先保存研究。定性和限值结果没有普通数值图时，仍可导出事实报告。需要以后复用时再点“保存为研究”，核对当前批次、分组、条件、检项和对齐范围，填写名称及依据后确认。保存为独立新研究，原研究保持不变。

已保存研究可从页首选择并直接重现原筛选与分组。在检测台账中新增“当前批次快速对比”，每张趋势卡新增“对比此检项”，带入当前项目、批次、条件及对应检项；台账本身的默认表格顺序、采用规则和来源核对入口不变。

## 页面与反馈

桌面端沿用 V3 导航、按钮和卡片，将选择区放在左侧、结果放在右侧，让首图直接可见。单个检项的图可用完整结果区宽度；多个身份仍分别出图。手机端改为纵向排列、批次横向选择，并提供“查看趋势”定位按钮。

页面显示所选批数、结果数、可绘制数值数和独立检测组数。无结果时提示调整范围；有结果却无精确采用值时提示查看完整原文，不保留一个没有说明的空图。单图失败可独立重试；完整结果失败有单独重试。批次、条件或检项变化时，清除旧图和旧下载按钮，并重新确认临时对齐。变更分组角色不扩大已确认身份范围。

目录、分组摘要、单图和完整表格分开读取。单图请求仅返回对应组曲线与溯源单元，完整表格按需读取；最多3个图表请求并发。切换范围／项目后中止旧请求并拒绝过期响应，不重算来源候选、不重新解析整本 Office。

HMW 继续默认0～5%概览，其他检项沿用0.1.4共享坐标规则，支持细节与不可裁点的手动范围。单图导出使用已经绘制成功的坐标；单组“导出当前范围”也复用已应用坐标，多组范围报告使用概览尺度。隐藏图例不改变纵轴。源数值、比较符、缺失与时间点保持原状。

## 后端和数据保护

新增 `GET /api/v1/projects/{project}/comparison-catalog`，在同一只读快照内提供批次、条件、检项选项、数量、研究列表与项目 revision。

新增 `POST /api/v1/projects/{project}/comparison-preview`。虽然使用 POST 传递明确范围，该接口仍只使用 SQLite 只读连接；不新增研究、事件、幂等记录、结果或项目修订。它校验所选样品归属、revision、允许对齐字段和确认依据，再复用 `comparability.py` 的相同分组与正式采用规则。默认返回摘要，按需返回单组图或完整单元。没有另写一套前端数值选择规则。

研究成员新增“selected／按批次对比”角色，研究 JSON 记录所选筛选范围；旧研究缺少该字段时仍使用原有默认范围。报告支持 quick 类型，冻结同一当前选择，不要求先保存研究。Excel、PNG、Word 和来源证据继续经过既有反读／哈希检查。相同批号的多个独立来源在显式对齐后仍保留各自曲线，不用同时间点结果覆盖另一条。

没有数据库迁移，也不更新原件、raw_json、正式身份、采用决定或上传版本排序。只有用户明确保存研究时才写入既有审计、幂等及修订；明确导出时才新增导出审计。查看、研究保存和报告导出继续分别校验权限，前端不自行提升角色。普通技术员可看图，报告导出仍需既有 export 能力。

实施前已备份 `data/` 至 `outputs/backups/pre-015-20261105-01/`，包括一致性 SQLite 与两份冻结原件。开发、保存和下载验收仅使用临时目录及 `outputs/quick-015-acceptance/home/`。日常库逐表行指纹与备份比较时还原备份原件路径，所有表及两份原件哈希一致，证据为 `outputs/quick-015-acceptance/daily-preservation.json`。

## 启动和失败定位

关闭旧服务后，在本目录重新运行 `start.cmd`，确认 `/health` 为0.1.5。导出需要 `start.cmd --role project_lead` 或已有管理员角色；仅看图不需要提升权限。无需转换数据库或重新入库。

若仍出现旧的大型“新建可比研究”表单，先核对运行目录、服务版本并刷新生成页面。若提示 `stale_revision` 或 `comparison_members`，刷新目录后重选，不能改库绕过。若有差异而分图，使用当前范围确认对齐；方法或单位差异继续分图。若没有可绘制数值，查看完整结果中的原文及采用状态，不将 ND 或限值改成0。

快速选择、状态、取消和页签在 `frontend/v3/quick-comparison.js`；目录及差异提示在 `quick_comparison.py`；统一身份／采用分组在 `comparability.py`；报告范围与反读在 `study_reports.py`、`workflow_excel_verify.py`。API错误保留具体原因；处理方式是修正请求或代码，不为展示修改正式数据库。
