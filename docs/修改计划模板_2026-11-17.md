复制以下任务卡，为每项功能单独填写；空项不能视为已经验证。

```markdown
### [编号] 修改标题
- 优先级 / 状态：P0/P1/P2；待核实/待实施/进行中/待验收/完成
- 用户问题：谁在什么操作中遇到什么现象。

- 范围与非目标：本任务修改哪些行为，哪些另立任务。
- 前置依赖：任务编号、共享契约、需要确认的业务规则。
- 修改位置：后端 / API与契约 / 前端 / 数据迁移 / 测试 / 文档。

- 验收用例：Given 前置数据 → When 操作 → Then 可观察结果。
- 异常用例：冲突、重复请求、过期页面、错误身份、失败回滚。
- 验收证据：页面 / API / 隔离数据库 / 导出反读，各自检查什么。
- 验证记录：实际命令、退出结果、证据路径；未运行明确写未运行。
- 回退方案：代码恢复路径；迁移失败后的独立备份恢复方式。
- 完成标准：全部必要用例通过；未解决项列明，不以按钮可见代替完成。
```

## 5. 关键实现约束与待决策事项

1. **清空与删除。** 网页明确清空可规划为作废动作，但上传文件的空白不能自动等同删除命令。删除行、表、样品的影响应展示引用清单；不采用附件建议的默认 `force=True` 无差别级联。跨研究共享结果究竟仅解除关联还是同时作废，是实施前需确定的业务语义。
2. **既有作废规则。** 旧计划要求作废显示状态而非普通空白；附件要求清空后可继续填数。建议空格可填但保留作废标识和历史入口；最终展示规则需统一。保留原版本，不自动采用更早版本。
3. **自动建档。** 附件同时描述“提交后自动补齐”和“一键同步”。目标保持无需逐批手建；自动执行时机及失败后的重试方式须确定。无论采用哪种方式，都不能生成重复样品、重复结果，或把未确认候选变成正式事实。
4. **0M 历史引用。** 新复制动作与旧引用模式分开处理。是否批量转换旧引用尚无明确决定；先保留旧语义，提供可预览的显式转换设计，不发布即静默转换。
5. **部分入库。** “正常新增不被冲突阻塞”应通过明确选择提交子集实现；选定子集仍保持事务原子性，未决冲突留待处理。不能在现有整表事务内吞掉异常后报告整表成功。
6. **身份与沙盒。** 样品唯一键需对照现有模型核实；不只按批号匹配。`TEST` 是拟议沙盒显示名称，项目类型/用途才是限制依据；“完整历史汇总表”的可判定条件需定义，不能只靠文件名或批次数猜测。
7. **超限提示。** 后端统一返回可解释的判定和标准版本，前端只负责样式。包含 `<`、`≤`、`>`、`≥` 的边界不能都压缩成闭区间；`ND`、`N/A`、定性值、单位不一致或不明确标准不自动判合格。
8. **模板与迁移。** “常熟版式”作为可选模板配置，不对某项目硬编码。真实模板须在本地逐格对照；迁移版本号根据当前迁移链分配，不直接照抄附件的 schema 19。

以上问题不阻塞代码核查与计划细化，仅阻塞依赖该决定的行为实现。

## 6. 最小端到端验收

| 路径 | 操作 | 必须看到的结果 |
|---|---|---|
| 新研究 | 标准/方案 → 样品 → COA → 0M 复制 → 修改 → 导出 | 身份一致；来源版本可查；复制后独立维护；新导出反读一致 |
| 历史研究 | 历史表核对 → 正式提交 → 批量建表 → 重试同步 | 删除线、双语冲突等沿用原核对；样品/表不重复；辅助图表数据不污染结果 |
| 增量维护 | 保留旧值、补新时间点、更正冲突、清空，再回传旧模板 | 不重复版本；更正留痕；作废不复活；旧模板冲突明确展示 |
| 关联影响 | 同批次加入两个研究后更正、作废底层结果 | 两个研究当前展示及新交付一致；角色独立；历史交付快照保持原样 |
| 受控导出 | 同条件选择多个批次导出并反读 | 表头、日期、签署文字、检项、单位、标准及事件归属正确；无额外超限染色 |
| 失败恢复 | 过期 revision、重复请求、错误身份、提交中断、迁移失败 | 拒绝越界和过期写入；幂等；失败不留下半套关联；隔离备份可恢复 |
