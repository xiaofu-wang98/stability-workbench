MVP 目标是让研究员在工作台完成来源归档与核对、项目和样品绑定、方案与标准建表、COA 与 0M、结果录入和回传、更正与作废、采用值查询及可追溯交付。覆盖有原件依据的历史研究，以及从计划到交付的新研究。每个正式结果应回指采用版本、样品、检项、时间点和来源。正式上线前另有隔离迁移和恢复关卡。

MVP 非目标为全量自动解析任意 Office 或扫描版式、用 LLM 或数值推断代替研究员解释、复刻所有历史 Excel 版式、让签署文字充当电子签名、自动给出质量合格或效期结论，以及未经授权切换、清理或回写日常库。复杂 PDF 全自动解析列为 `OUT-OF-SCOPE`。已承诺的归档、人工核对、检索与来源回读仍按对应关卡验收。

## 2. 状态及证据判定

| 状态 | 使用条件 |
| --- | --- |
| `PASS` | 约定场景及所需证据齐全，且与冻结预期相符。注明代码版本、样本及范围。 |
| `FAIL-CODE` | 已复现的逻辑、数据、接口、产物或测试脚本缺陷。记录实际行为及失败断言。 |
| `FAIL-UX` | 正常入口、提示、恢复或确认流程的可复现缺陷。记录受影响角色、步骤和页面证据。 |
| `BLOCKED-BUSINESS` | 缺少批准资料或业务选择，无法为具体场景确定正式预期。记录待决项和受阻范围。 |
| `NOT-VERIFIED` | 只有代码、计划、相邻测试、旧断言或汇总声明，缺对应范围的实测证据。 |
| `OUT-OF-SCOPE` | 当前 MVP 明确排除的场景。范围变更需记入本合同。 |

一次记录以一个可判定场景为单位。接口成功、页面按钮可见、全量测试计数和历史报告中的完成措辞各有覆盖范围。故障修复后以同场景的复测关闭。预期的权限拒绝、冲突拦截和待确认提示，只要与约定一致，其用例可判 `PASS`。模拟值或模拟裁决只证明流程。阶段必过项出现任何失败、待确认或未验证时，该关卡仍开放。批准的范围排除要写明理由和影响。

证据最小记录包括场景编号、提交与树、隔离库和 schema、原件 SHA256 及页／表／格、操作角色和步骤、冻结预期、实际 HTTP 及业务错误码、必要页面截图、重开后的 API 或只读数据库观察。涉及写操作时保留版本、审计与对象 ID 的前后差异。涉及交付时保留下载文件哈希、快照 ID 和独立反读结果。失败保留可重放步骤。业务原件、数据库、日志和产物留在本地隔离目录。
