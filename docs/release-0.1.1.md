# 0.1.1（2026-11-02）

## 未划线全文预览确认

原格删除旧英文后仍有中文和新英文时，原实现将其一律视为多条结果。现在允许明确的两行定性双语段落预览并完整保留未划线文字，标题明确显示“完整保留未划线内容（中英文全文）”。不把整段保留解释成系统认可翻译等价。

仅扩展定性文字：不一致的数字、多个同语言结果、三行及以上结果、带测量标签/限值/百分号的多行结果、已知正反结论和身份冲突仍需明确解释；结构风险不开放该建议。中英文方法或子结果冲突、批注、公式、数值格式等独立问题不会因保留文字而批准。沿用原有预览指纹、权限、revision、幂等、审计、撤销和整表提交，无迁移，不改写原件或正式版本。

## 保存后的计算

- `saved_changes` 一次按物理来源索引候选，判断整行或部分排除；字段关联同样按坐标索引。消除“每个排除候选/每个修改 × 全部候选”的扫描及 Location 对象比较。
- 无字典及身份关联时，未变化来源的映射不再因为已有正式历史而全量失效。候选原文、修订、纠正、来源决定、生命周期、上下文或配置变化会失效；当前正式历史的值比较和跨候选身份碰撞仍重新检查，最终提交仍强制新鲜映射。
- 一次快照事务中的预检共用批量历史版本及采用选择；事务中任意写入后重新加载。缓存不跨连接共享，非事务查询继续实时读取。

## 验证及性能边界

使用 5,849 个候选、8 张表的 IP281 SQLite backup 副本验证；日常数据库不用于写入测试。与 0.1.0 的 `saved_changes` 在同一候选快照上比较，输出逐项相同，未开启 profiler 的耗时为 **6.29 秒 → 0.49 秒**（约快 12.7 倍）。该数值不同于此前含 profiler 开销的 14.2 秒。

真实删改任务在副本上完成预览、保存和增量重读：预览 0.011 秒、保存 2.48 秒、保存后后台刷新 1.01 秒、无变化读取 0.003 秒。保存重新映射 1 个候选，刷新重新映射 0 个；仅 1 个候选更新。计时为本机服务层，不含浏览器绘制与 HTTP 传输。

首次冷读取仍需完整建立来源与全表资格（本次约 15.4 秒），变化后也仍运行全表身份碰撞/资格检查；并未把安全检查替换成仅看单格。增量响应仍含核对元数据，本次约 7.9 MB，有后续压缩空间，不能宣称所有页面读取均在 1 秒内。

回归覆盖全文保留预览/保存/幂等/重读/撤销，数值与多结果拦截，独立方法/子结果冲突保留，大量整行及部分排除，映射复用后正式历史变化，事务内采用变更及回滚。页面基线验证布局、桌面/移动端和 JavaScript 错误。
