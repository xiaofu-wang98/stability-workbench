## 流程

1. 原表按钮直接说明问题：明确本行检测分项，或明确中英文方法/分项含义。
2. 展示批号、条件、原检测项、方法以及受影响结果数量；可展开各时间点原始结果并定位原格。合并结果显示物理范围和逻辑行，避免一格多结果混淆。
3. 只填写问题字段。名称不明确时只输入完整检测项/分项名称；有中英文冲突时点选中文、英文，或自行明确。公式/数值解释直接填写对应字段。
4. 同一原表逻辑行的其他时间点存在唯一明确名称时，提供带原文依据的候选按钮，不预选、不自动采用。不同工作表、批次、方案、逻辑行不会提供名称；有修订或冲突的来源不提供候选。没有唯一依据时人工填写。
5. 预览修改前后、关联时间点和各自保留的结果。可返回修改且保留输入和依据，再明确保存草稿。较长内容在弹窗内滚动，依据和操作按钮保持可见。

同一共同来源的多个时间点沿用既有任务归组，一次明确名称/方法，但各时间点不会复制同一个结果。其他独立问题、整表确认、权限、revision、预览指纹、幂等和事务仍由原流程处理。

## 后端与历史边界

- 分项缺名/多含义的系统提示附带机器可读类型与必填字段，旧冻结提示通过原诊断文本兼容识别，不按项目、表名或坐标判断。
- 名称问题不再接受仅改结果、保留正文或使用“报告数据”“原表分项…（未命名）”解除。允许陌生分项词汇。
- 未入库草稿中的旧结果式决定不能作为名称已经解决的证据，原更正和审计事件保留；可能需要重新明确名称。如果旧草稿曾错误改过结果，仍需另行核对结果，不会自动恢复。
- 正式版本、原始文件、raw_json 均不重写；此前已入库错误不自动修正，仍走正式更正/身份关联流程。
- 删除线、实际批注、表后业务备注、AR/OOS 等业务解释及正式采用规则没有改动。通用原文批注仍使用原有弹窗。
- 没有增加数据库迁移，没有引入 AI。
