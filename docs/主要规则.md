# 主要规则

1. 原始文件与SHA256冻结保存。人工解释、工作副本、原始事实、正式采用值分别保存；不覆盖原件、raw_json或已提交版本。
2. 内部ID由系统产生，原始Word/Excel不需要填写系统ID。项目、材料类别DS/DP、用途、批号、规格、研究类型、条件、方法、子结果和报告标准体系分别表达。
3. 上传与接收只是形成可核对来源。仅整表预检通过后的事务提交产生正式事实；有争议的草稿不进入正式汇总。
4. 含义冲突必须由人解释。Monomer/HMW、中文还原/英文NR等不能默认选中文、英文或按数值猜测。合并多个来源不证明结果相同。
5. 数值保留比较符、单位和源格式。百分比按冻结规则解释；ND、限值、文字、不汇报不制造0。不同标准体系的报告值不混为一条。
6. 删除线、批注、公式、未知区域与结构问题各自处理。批准一个问题不批准其他问题；表后备注按行限制到相应时间点与检项。
7. 人工兜底工作副本支持改单元格、清空/不采用、合并、拆分与局部撤销。每条人工结果绑定原件非空格；一格可明确拆成多条，一条可明确引用多格。原件没有的新增空格只能作为排版，不能冒充原始数据来源。
8. 结果清单须明确检项、时间点和值，其他必要身份仍由既有预检检查。删除清单行会在精确预览中列为所选来源的不采用；未选范围不受影响。纯排版编辑不会自动重解释全部工作表。
9. 工作副本先预览，再填写依据并确认全部列出的来源问题。人工结果不得通过原中英文矛盾标签重放为已解决；未知语义仍待人指定。
10. 权限统一由后端检查。普通技术员可处理自己的未入库草稿；对其他上传者的人工重建/排除/恢复需要高级能力。只读角色不能保存。前端隐藏按钮不代替后端权限。
11. 所有保存检查项目revision、明确来源范围与预览指纹，使用幂等键；事务失败整批回滚。保存重试不重复建候选。撤销拒绝后续改动与正式结果。
12. 台账读取在同一数据库快照完成。缓存按上传、项目修订及操作者权限隔离；无变化刷新返回轻量通知并不重绘表格。完整响应以不可变JSON缓存并在读取时还原独立对象，每次仍校验冻结原件哈希。进程重启的首次打开仍运行完整解析核对。
13. Excel与PNG从同一筛选快照输出并独立反读验证；人工兜底后的结果沿用相同导出规则和原格溯源，不伪造原始值。
14. 业务代码不使用项目号、表名或坐标白名单。测试中的合成坐标仅用于构造独立案例。历史正式数据与未确认业务身份不因发布版本而自动变更。
15. 定性双语段落可经预览确认完整保留未划线文字；这不证明翻译等价，也不解除其他含义、方法、身份或来源问题。多结果、数值不一致、测量标签和结构风险继续要求明确解释。保存后可复用未变化候选的来源映射，但必须依据当前历史重判比较与身份碰撞，正式提交仍执行完整核验。

当前兜底编辑面向.xlsx工作表，不提供Excel公式计算、图片OCR、宏、整本Excel功能或原件编辑。未识别的来源可以人工绑定原格并填写结果身份，剩余未知区域仍需明确用途；正式提交后使用既有更正和复核流程。
