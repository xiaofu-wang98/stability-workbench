# 真实结果展示接入方案（基于 0.1.1）

日期：2026-11-04。状态：方案已按用户三项答复确认，后续已获用户明确实施授权。实施与验收见 `release-0.1.2.md`。用户要求沿用此前交互习惯、复用现有代码，业务冲突先确认。该文档记录方案基线；实施过程不得为适配展示而改写业务数据库或已确认结果。

## 一、历次升级留下的展示规则

## 二、结果进入展示的边界

流程为：冻结来源 → 解析/人工工作副本 → 核对草稿 → 整表预检与提交 → 结果版本/采用决定 → 正式结果查询 → 表格、趋势、导出。

1. 上传成功、接收成功、草稿保存成功都不等于形成可用于正式汇总的结果。未提交草稿和被排除来源不画成趋势点。
2. 已提交版本仍区分“展示值”和“正式采用值”。待复核的新展示值按既有规则提示，不能被描绘成已正式采用。
3. 同值重复来源保留多来源溯源，不因重复上传制造多个时间点。独立复测保留检测身份与版本；默认每个槽位的显示/采用选择仍由后端决定。
4. 正式更正、采用选择与复测的既有权限和历史不由展示页面改写。图例开关、筛选与隐藏曲线都只是查看操作。
5. 最新版本的排序是业务规则，前端不按上传文件名、数组顺序、检测日期或单元格位置自行另选。

## 三、沿用既有交互的页面方案

继续使用现有“数据接收 / 检测台账 / 可比性研究 / 报告中心”。用户已确认本轮范围为检测台账真实矩阵、稳定性趋势及同范围导出；可比性研究单列后续阶段。

检测台账内部顺序：

1. 项目与当前样品信息、标准关联状态。
2. 放行 / 稳定性 / 影响因素分区，批号选择，长期/加速研究及条件筛选。
3. 完整结果矩阵。
4. 与所选范围对应的趋势图区和查看提示。
5. 当前范围的 Excel / PNG 输出入口；来源文件核对维持已有切换入口。

具体交互：

- 进入 `?project=...&view=ledger` 默认查看结果汇总；带 `upload`、`sheet` 的链接继续精确定位来源核对。两种入口不能互相冒充。
- 单批次查看沿用原习惯；记住当前项目最近使用的有效批号、分区、研究和条件。切换项目时只恢复该项目自己的选择，不沿用其他项目的批号。
- 稳定性矩阵以检项/子结果及方法为行、时间为列。同一批号内的材料类别、规格、研究或条件不同，保持清晰分组。
- 放行保留“按检测项目 / 按批次”两种方向，图按需展开；影响因素支持按天显示，不强制变成月。
- 保留参考品用途、DS/DP、标准报告体系；“参考品”不能代替研究类型或材料类别。
- 表格先呈现，图表随后异步加载；图表请求失败不清除已经读取成功的表格。
- 点击结果格沿用来源抽屉；点击图点打开同一结果版本的值、单位、状态、来源工作表/坐标与变更历史，允许定位回原表。
- 字段未知时显示清晰的“原文未注明/待关联”及来源范围提示；内部ID不直接作为正文。但不能因隐藏内部ID就把不同的未知身份合并。

## 四、统一数据口径

### 4.1 表格、图表与导出

用户已确认沿用既有双状态表格：展示值与正式采用值有差异时明确列出，待确认值保留颜色和文字提示。趋势图默认正式采用值，并显示当前口径；若表中展示值与图点不同，在该格和图上说明原因。

不将表格默认改成只显示正式采用值；后端保留两种值，界面不可悄悄覆盖。Excel继续保留双状态，PNG与页面趋势默认使用正式采用值，输出中明确标注口径。

所有页面数据携带一致的项目修订和所选范围。请求期间版本变化时提示更新并一致刷新；导出记录项目修订、结果口径、筛选范围、结果版本和来源，不允许旧表与新图混在同一“当前版本”下。

### 4.2 图表分组与曲线

- 图表的检测项来自当前真实结果，不硬编码只画 SEC、HMW、NRCE、icIEF。
- 单图只包含一致的材料类别、规格、用途、研究/研究编号、条件、检项/子结果、方法/版本、标准报告体系、单位、时间单位。批号可作为多条曲线，但跨批次叠加必须明确选择，且其余维度兼容。
- 同名不证明同一身份；不把不同方法、单体/HMW、中/欧/美标准结果合为一条线。未建立明确关联的来源限定“未知研究/规格”不能自动跨来源拼接。
- 横轴按实际天数/月数数值排序，不按字符串排序或按等距类别掩盖真实时间间隔。0M、1M、3M按真实位置放点；天和月不自动换算混图。
- 只给明确数值结果绘制数值点。百分比和单位使用后端已冻结解释，前端不解析显示文字或再做单位换算。
- `<0.1`、`>99`、ND、N/A、文字、不汇报等保留原文及原因，不作为普通精确数值点；定性项目仍在矩阵中完整展示，并说明不能生成数值曲线。
- 明确存在的缺项或特殊值位置断线，不补0、不插值、不跨缺口连线。横轴可采用当前兼容范围已收到时间点的并集；没有研究计划时不凭空生成应检时间，也不推断未到期/未检测。
- 只有一个数值时显示点和“仅1个有效时间点”，不声称形成趋势；无有效数值时展示原因。曲线采用直线连接已知相邻有效点，不套用原演示的平滑降解假设。
- 图例开关控制可见曲线，悬浮显示批号、时间、原始值/精确显示值、单位、口径；跨批次曲线不自动获得“变更前/后”角色。

### 4.3 标准与评价

旧图固定的95%、4.5%等限度不得回放到真实项目。只有检项、方法、适用范围及标准版本已明确且限度可结构化表达时，才具备绘制限度的基础。

首阶段保留真实关联状态和标准原文；可复用的限度处理没有验证前不承诺自动限度线/合格判定。未关联或多版本不明时明确提示。没有标准、没有完成评价，不阻止查看与合法范围导出；不自动生成合格、有效期、降解速率或可比性结论。

## 五、局部接线与复用边界

本轮以现有页面和Python模块化单体为基础，先补接线与必要的只读结构化结果，不迁移UI框架、不另造确认流程。

| 已有模块 | 本轮复用/补齐 |
|---|---|
| `result_queries.py`、`identity_associations.py` | 继续作为展示/正式采用选择的唯一依据；复用已有身份关联与版本决定 |
| `v45-ledger.js`、`v4-result-cell.js` | 继续负责真实分区、矩阵、单元格状态和来源详情，局部补齐旧交互与曲线入口 |
| 原 `template.html` 图表区域、Chart.js | 复用容器与图例/悬浮信息；以真实检项动态生成，去掉真实路径对IP166E样例数组的依赖 |
| `trend_export.py` | 抽用/复用图表范围和点语义；补充缺口结构，使页面和PNG对特殊值、断线规则一致 |
| `result_snapshot.py`、`workflow_excel.py` | 沿用版本快照、双状态、范围、Excel/PNG输出与反读；补足当前查看范围、口径的传递 |
| `v4-source-drawer.js` | 图点、表格共享一个来源/历史详情入口 |

当前 result-cells 返回的值主要是格式化文字，不能在浏览器用 `parseFloat` 构造图点。宜小幅扩充只读查询，提供精确数值字符串、比较符、状态、单位、时间、版本及来源引用，并让页面与PNG共享范围校验和点分类。

当前完整导出快照会扫描草稿和来源覆盖，不适合每次选检项都运行。日常图表请求只读已提交结果及其身份/采用状态，不调用原表 `ledger-matrix`、不重新解析Office文件；完整输出审查留在用户明确导出时执行。

旧Chart.js来自外网CDN；正式本地运行应固定版本并随应用本地加载，保留许可。图表库缺失时明确报错，表格仍可用。

## 六、性能和读写约束

- 切批号、条件或检项只查询必要结果/曲线，禁止重新建立整个文件的解析、候选和预检。
- 表格可先呈现当前批次范围；列表分页必须完整读取或后端按完整范围聚合，不能把第一页当成全部结果统计或绘图。
- 结果缓存按项目修订、权限、筛选及值口径隔离；前端防止较慢旧请求覆盖新选择。无变化刷新继续轻量处理。
- 只加载当前检项/可见图，避免对每个检项一次生成大量画布；具体阈值以IP275及IP281副本实测后确定，不把未测数字写成保证。
- 入库后返回展示页时更新结果修订与图表；浏览结果不触发确认、采用、来源重解释或隐式写入。

## 七、实施顺序与验收

### 阶段1：结果台账

恢复批次/研究/条件交互，核对真实分区、完整矩阵、双状态、来源详情和未知身份的友好显示。先在已入库IP275副本走通，再检查含历史冲突的场景。不得重做用户已经完成的入库决定。

### 阶段2：稳定性真实趋势

为选定范围提供结构化图点并接到旧图表区域；处理定性文字、特殊值、缺口、单点、无数据、图点溯源、本地离线加载和竞态。与既有PNG共享实际含义。

### 阶段3：同范围输出与回归

页面与Excel/PNG核对项目、修订、检项/方法/单位、时间、版本、来源及结果口径；导出范围明确。可比性研究接入留在后续独立阶段。

验收必须覆盖：

1. IP275已入库结果正常显示，无需重新上传或重新确认；从来源核对和结果汇总可来回定位。
2. 长期、加速、影响因素、放行分区及DS/DP/参考品用途不串值；天/月不同轴，未知身份不误合并。
3. 草稿/排除来源不入图；待确认展示值与旧正式采用值同时存在时，表图准确标出口径。
4. 图点与同口径表格一致；多来源不重复画点，独立复测不被丢弃历史。
5. 特殊值、缺项、百分比、中文文字、多个标准体系、单点/无数值和长精度值不被误算。
6. 无关联标准时不出现演示限度或合格标识；已有研究分组不被新上传或页面筛选改写。
7. Excel和PNG独立反读通过；所选范围/口径变化不会下载旧缓存文件。
8. 断网、刷新、重启、跨项目切换、连续快速换检项、只读角色均符合既有交互与权限。
9. 报告首次读取与切换/刷新耗时、响应体积和重算范围；不以缓存命中掩盖冷启动，不让正常浏览回退到全量原表重算。

## 八、用户已确认的实施口径（2026-11-04）

1. **表图默认口径**：沿用双状态表格＋正式采用值趋势，并显式提示差异。
2. **本轮范围**：先完成检测台账的真实结果矩阵、稳定性趋势图和同范围导出；可比性研究单列后续阶段。
3. **最新值排序**：沿用现有后端版本规则，不改变已有最新值排序；检测完成日期排序另行定义，不纳入本轮。

三项均来自用户对方案选择题的明确答复。其余已经明确的归属、权限、状态、来源和标准规则继续沿用。此次答复用于确定方案，不将其扩展解释为立即修改产品代码的指令。
